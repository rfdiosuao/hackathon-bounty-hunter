# 黑客松拿奖核心心法：最小可演示闭环（Minimum Demo Loop）

> **黑客松拿奖 ≠ 把项目做完。** 用 20% 的功能做出 80% 的演示效果，才是最高性价比。

---

## 一、为什么"做完"是陷阱

黑客松评审看的是**演示那一刻的冲击力**，不是代码完整度。

| 错误做法 | 正确做法 |
|---|---|
| 想把所有功能都做完 | 只做一个能跑通的核心闭环 |
| 最后一刻还在加功能 | 提前 2 天锁定功能，只做优化 |
| 演示时说"这个功能还没做完" | 演示时每一步都流畅、有反馈 |
| 功能多但每个都半成品 | 功能少但每个都精致、有 UI 质感 |

**铁律：评审记住的是你演示时最炸的那 30 秒，不是你写了多少行代码。**

---

## 二、什么是"最小可演示闭环"

一个最小可演示闭环 = **用户从进入到获得核心价值的完整路径，每一步都能跑通、有反馈、UI 不崩。**

### 闭环三要素

1. **入口清晰**：用户打开就知道要做什么（3 秒内理解）
2. **核心动作可执行**：最关键的那个功能必须真的能跑（不是截图、不是 mock）
3. **结果有反馈**：做完之后有明确的输出/奖励/惊喜感

### 反例（不是闭环）

- 首页做得很漂亮，但点"开始"之后是空白页
- 核心功能用假数据演示，一交互就崩
- 流程走到一半提示"功能开发中"
- 只有设计稿，没有可交互的东西

### 正例（是闭环）

- 「城市盲盒」：打开 → 看到 3 个任务 → 选一个 → 模拟到达 → 解锁故事 → 获得徽章。**每一步都能点、都有反馈、UI 统一。**
- 哪怕"到达验证"用的是模拟按钮（不是真 GPS），只要流程跑通、故事真的生成了，就是合格的 demo。

---

## 三、功能砍除法：必须做 vs 可以砍

### 必须做（核心闭环内）

- [ ] 首页/入口页（UI 要炸）
- [ ] 核心功能的完整交互流程
- [ ] 1-2 个"哇时刻"（让评审眼前一亮的点）
- [ ] 结果页/输出页（有成就感）
- [ ] 错误处理（点错了不崩、有友好提示）
- [ ] 移动端适配（评审大概率用手机看）

### 可以砍（闭环外）

- [ ] 用户注册/登录系统（用 mock 登录或直接跳过）
- [ ] 设置页、个人中心、历史记录
- [ ] 分享功能（演示时不需要真分享，有按钮就行）
- [ ] 多角色/多场景（只做一个最炸的场景）
- [ ] 数据持久化（用内存/本地存储就行，不用后端数据库）
- [ ] 复杂的后端逻辑（能前端 mock 就 mock）
- [ ] 性能优化（demo 不卡就行）
- [ ] 单元测试、CI/CD
- [ ] 多语言、暗色模式

### 判断标准

问自己：**"评审演示时，这个功能会被点到吗？"**
- 会被点到 → 必须做，而且要做好
- 不会被点到 → 砍掉，或者只放一个按钮（点了提示"敬请期待"）

## 四、演示优先级排序

按这个顺序投入时间，前面的没做好就不要做后面的：

| 优先级 | 内容 | 投入占比 |
|---|---|---|
| P0 | 核心闭环能跑通（不崩、流程完整） | 40% |
| P1 | UI 视觉统一且有质感（首页 + 核心页） | 25% |
| P2 | "哇时刻"（AI 生成结果/动效/惊喜感） | 15% |
| P3 | 交互细节（按钮反馈、过渡动画、错误提示） | 10% |
| P4 | 额外功能、边缘场景 | 10% |

**关键：P0 和 P1 占了 65% 的时间。UI 好看 + 流程能跑 = 已经赢了 70% 的队伍。**

## 五、时间分配原则（以 48 小时黑客松为例）

| 阶段 | 时间 | 做什么 | 产出 |
|---|---|---|---|
| 第 1 小时 | 0-1h | 确定 idea + 画核心流程图（3 个页面以内） | 纸面原型 |
| 设计阶段 | 1-6h | 定风格 + 做首页和核心页设计稿 | 设计图 |
| 核心开发 | 6-24h | 只做核心闭环，其他全部不做 | 可跑通的 demo |
| UI 打磨 | 24-36h | 统一视觉、加动效、修细节 | 好看的 demo |
| 演示准备 | 36-42h | 写路演讲稿、录演示视频、彩排 | 路演材料 |
| 缓冲 | 42-48h | 修 bug、微调、休息 | 稳定版本 |

**红线：比赛结束前 6 小时，绝对不加新功能。只修 bug、只做优化。**

## 六、"哇时刻"设计（拿奖关键）

一个 demo 至少要有 **1 个"哇时刻"**——评审看到会眼前一亮、记住你的点。

常见的哇时刻：
- **AI 生成结果惊艳**：输入简单，输出超出预期（如 AI 生成的故事/图片/视频）
- **交互有惊喜**：点击后有意外的动效/反馈/彩蛋
- **视觉冲击力**：首页一打开就"哇"（参考秒哒获奖作品）
- **数据真实感**：用真实数据/真实场景，不是假大空
- **社会价值钩子**：解决了一个真实痛点，有情感共鸣

**设计方法：在核心闭环的"结果页"下功夫。** 用户走完流程后的那一刻，就是哇时刻的最佳位置。

## 七、检查清单：你的 demo 达到最小闭环了吗？

演示前逐项检查，任何一项不过关就优先修：

### 流程完整性
- [ ] 从打开到获得核心价值，全程能走通，没有"开发中"
- [ ] 每一步都有明确的下一步指引
- [ ] 返回/重试都能正常工作

### 视觉统一
- [ ] 所有页面颜色、字体、间距风格一致
- [ ] 首页有视觉冲击力（3 秒内抓住注意力）
- [ ] 没有空白页、没有占位符文字

### 交互反馈
- [ ] 每个按钮点击都有反馈（变色/缩放/loading）
- [ ] 加载状态有提示（不是白屏等待）
- [ ] 错误场景有友好提示（不是崩溃/报错）

### 演示可控
- [ ] 演示路径提前彩排过，知道每一步点哪里
- [ ] 有备选方案（网络断了/API 挂了怎么办）
- [ ] 演示时间控制在 3 分钟以内

### 哇时刻
- [ ] 至少有一个让评审"哇"的点
- [ ] 哇时刻出现在演示的黄金位置（中段或结尾）

## 八、常见陷阱

1. **"再加一个功能就完美了"** → 不存在完美，加功能只会引入新 bug。锁定闭环后只做减法。
2. **"这个功能很简单，10 分钟就做完"** → 永远不止 10 分钟。简单功能也会牵扯 UI、交互、错误处理。
3. **"先把功能做完再美化 UI"** → 错。UI 和功能同步做，最后统一打磨。UI 是评审的第一印象。
4. **"我要做一个平台级产品"** → 黑客松 48 小时做不出平台。做一个场景、一个用户、一个核心动作。
5. **"演示时解释一下就行"** → 评审不听解释，只看屏幕。屏幕上是什么就是什么。

---

## 九、一句话总结

> **做少、做精、做炸。**
> 核心闭环跑通 + UI 有质感 + 一个哇时刻 = 黑客松获奖公式。
> 剩下的，都是锦上添花，不是雪中送炭。

---
