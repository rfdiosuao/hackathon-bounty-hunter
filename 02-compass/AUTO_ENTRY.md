# 🤖 阶段 2.5：自动参赛 Agent（Auto Entry）

> 线上比赛太多参加不过来？让 Agent 自动挑项目、自动包装、自动提交。
> 你只需要在最后一步点确认。

---

## 一、这个模块解决什么问题

**痛点**：雷达每天推送十几个比赛，根本参加不过来。线下比赛去不了，但大量线上比赛只需要提交项目链接+说明文档，完全可以自动化。

**解决方案**：Agent 自动完成「筛选线上比赛 → 扫描你的 GitHub → AI 匹配最优项目 → 自动包装提交材料 → 半自动提交」。

---

## 二、能全自动 vs 需要人工确认

| 环节 | 自动化程度 | 说明 |
|---|---|---|
| 筛选线上比赛 | ✅ 全自动 | 过滤掉线下/需要现场开发的比赛 |
| 扫描 GitHub 仓库 | ✅ 全自动 | GitHub API 读取所有仓库 |
| 项目-比赛 AI 匹配 | ✅ 全自动 | 大模型打分，输出 Top 3 匹配 |
| 生成提交材料 | ✅ 全自动 | README、项目描述、演示脚本、标签 |
| 填写报名表 | ⚠️ 半自动 | 需要用户提供个人信息模板，自动填入 |
| 上传项目链接 | ✅ 全自动 | GitHub 链接直接填 |
| 邮箱验证/协议签署 | ❌ 人工确认 | 涉及法律责任，必须本人操作 |
| 最终提交 | ❌ 人工确认 | 提交前给用户预览，确认后才提交 |

**原则**：Agent 做 90% 的准备工作，最后 10% 的提交动作由用户确认。绝不擅自提交。

---

## 三、什么样的比赛适合自动参赛

**必须同时满足**：
1. ✅ 线上比赛（不需要到现场）
2. ✅ 提交制（提交已有项目/作品，不是现场开发）
3. ✅ 允许个人参赛（不需要组队）
4. ✅ 报名免费（不需要付费）
5. ✅ 提交材料简单（项目链接 + 描述 + 可选视频）

**典型平台**：
- Devpost（大部分线上黑客松）
- Lablab.ai（AI 应用黑客松，提交制为主）
- 阿里云/腾讯云开发者大赛（线上提交）
- 各类 AI 应用挑战赛（提交 Demo 链接）

**不适合**：
- 48 小时现场开发黑客松
- 需要组队且人数 >1 的比赛
- 需要线下答辩/路演的比赛
- 有严格原创性要求（必须比赛期间从零开发）

## 四、核心流程

```
┌─────────────────────────────────────────────────────────┐
│  Step 1: 筛选可自动参赛的比赛                              │
│  从雷达推送的比赛中，过滤出线上+提交制+免费+个人可参加的      │
└──────────────────────┬──────────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────────┐
│  Step 2: 扫描用户 GitHub 仓库                              │
│  读取所有仓库：名称、描述、技术栈、README、star、最近更新     │
│  按质量排序（star数+更新时间+README完整度）                  │
└──────────────────────┬──────────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────────┐
│  Step 3: AI 匹配（项目 × 比赛）                             │
│  对每个「比赛-项目」对打分：                                │
│  - 主题匹配度（项目是否符合赛题方向）                        │
│  - 技术栈匹配（比赛要求的技术 vs 项目用的技术）              │
│  - 完成度（项目是否足够完整可展示）                          │
│  - 差异化（这个项目在该比赛中是否有竞争力）                  │
│  输出：每个比赛的 Top 3 推荐项目 + 匹配理由                  │
└──────────────────────┬──────────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────────┐
│  Step 4: 自动包装（为每个匹配生成比赛专用材料）              │
│  - 比赛专用 README（突出符合赛题的功能，重写项目介绍）       │
│  - 项目描述（200字/500字两版，针对比赛评分维度）            │
│  - 演示视频脚本（30秒/3分钟，告诉用户录什么）              │
│  - 标签/分类（比赛要求的赛道选择建议）                      │
│  - 提交说明（创新点、技术难点、社会价值）                    │
└──────────────────────┬──────────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────────┐
│  Step 5: 生成提交预览包                                    │
│  一个文件夹包含：                                          │
│  - README.md（比赛专用版）                                 │
│  - submission.md（提交表单需要填的所有内容，直接复制粘贴）   │
│  - demo_script.md（演示视频脚本）                          │
│  - match_report.md（为什么选这个项目参加这个比赛）          │
└──────────────────────┬──────────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────────┐
│  Step 6: 用户确认 → 半自动提交                             │
│  - 推送预览包给用户（飞书/邮件）                           │
│  - 用户确认后，自动打开比赛报名页，预填所有字段             │
│  - 需要人工的步骤（邮箱验证、协议签署）提醒用户完成         │
│  - 用户点最终提交                                          │
└─────────────────────────────────────────────────────────┘
```

## 五、AI 匹配评分模型

对每个「比赛 × 项目」组合，大模型按以下维度打分（0-100）：

```
总分 = 主题匹配 × 0.35 + 技术匹配 × 0.20 + 完成度 × 0.20 + 差异化 × 0.15 + 可包装性 × 0.10
```

| 维度 | 评分依据 |
|---|---|
| **主题匹配** | 项目核心功能是否符合比赛主题/赛道要求 |
| **技术匹配** | 比赛指定/鼓励的技术栈，项目是否使用 |
| **完成度** | 项目是否有可运行的 Demo、完整 README、截图/视频 |
| **差异化** | 相比该比赛常见参赛项目，这个项目是否有独特性 |
| **可包装性** | 能否通过改 README/描述就包装成符合比赛的样子 |

**输出格式**：
```json
{
  "competition": "比赛名称",
  "project": "仓库名",
  "total_score": 85,
  "dimension_scores": {
    "theme_match": 90,
    "tech_match": 80,
    "completeness": 85,
    "differentiation": 80,
    "packability": 90
  },
  "match_reason": "这个项目是AI客服机器人，比赛主题是企业级AI应用，技术栈完全匹配...",
  "packaging_advice": "建议突出多轮对话能力和企业知识库接入，弱化个人助手定位..."
}
```

## 六、自动包装模板

### 比赛专用 README 结构
```markdown
# {项目名} — {比赛名}参赛作品

## 一句话介绍
{针对比赛主题的一句话定位}

## 解决什么问题
{比赛相关的痛点场景}

## 核心功能
{3-5个最符合比赛评分维度的功能，每个配截图}

## 技术架构
{突出比赛鼓励的技术点}

## 创新点
{针对比赛评审标准的差异化说明}

## 演示
{视频链接 + 在线 Demo 链接}

## 团队
{个人/团队信息}

## 致谢
{比赛主办方、使用的开源项目}
```

### 提交表单内容模板
- **项目名称**：{不超过 30 字}
- **一句话描述**：{不超过 100 字}
- **详细描述**：{300-500 字，按比赛评分维度组织}
- **创新点**：{3 条，每条不超过 50 字}
- **技术栈**：{逗号分隔}
- **GitHub 链接**：{自动填入}
- **演示视频**：{提示用户录制后填入}
- **赛道选择**：{AI 建议的最匹配赛道}

## 七、使用方法

### 前置配置
1. 在 config.json 中填入 GitHub Personal Access Token（读取仓库用）
2. 填入个人信息模板（姓名、邮箱、简介，用于自动填表）
3. 配置推送通道（飞书/邮件，用于接收预览包）

### 运行
```bash
python3 02-compass/auto_entry.py
```

### 输出
- 每个可自动参赛的比赛，生成一个预览包文件夹
- 推送给用户确认
- 用户确认后，半自动完成提交

## 八、安全与合规

1. **绝不擅自提交**：所有提交动作必须用户确认
2. **原创性检查**：自动检查比赛规则是否允许"已有项目参赛"，不允许的跳过
3. **个人信息保护**：个人信息只存在本地 config，不提交到 git
4. **频率控制**：每天最多推荐 3 个比赛，避免用户疲劳
5. **质量优先**：匹配度低于 70 分的不推荐，宁可不参加也不要乱投

## 九、与现有模块的关系

```
01-radar（情报雷达）→ 发现比赛
       ↓
02-compass（筛选罗盘）→ 评估胜率
       ↓
02.5-auto-entry（自动参赛）← 本模块：线上比赛自动匹配+包装+提交
       ↓
03-pathfinder（深度分析）→ 需要深度准备的比赛走这里
       ↓
04~07（设计/开发/路演/复盘）
```

自动参赛模块是**轻量通道**：适合线上提交制比赛，快速批量参加。
深度分析模块是**重量通道**：适合高奖金、需要现场开发的重点比赛。
