# 🤖 阶段 2.5：自动参赛 Agent（Auto Entry）

> 线上比赛太多参加不过来？让 Agent 自动挑项目、自动包装、自动提交、自动跟踪结果。
> 你只需要在最后一步点确认。

---

## 一、这个模块解决什么问题

**痛点**：雷达每天推送十几个比赛，根本参加不过来。线下比赛去不了，但大量线上比赛只需要提交项目链接+说明文档，完全可以自动化。提交完还没人跟踪结果，获奖了都可能错过。

**解决方案**：Agent 自动完成「筛选线上比赛 → 扫描你的 GitHub → AI 匹配最优项目 → 自动包装提交材料 → 半自动提交 → 自动跟踪结果 → 获奖/未获奖自动触发复盘」。

---

## 二、能全自动 vs 需要人工确认

| 环节 | 自动化程度 | 说明 |
|---|---|---|
| 筛选线上比赛 | ✅ 全自动 | 过滤掉线下/需要现场开发的比赛 |
| 扫描 GitHub 仓库 | ✅ 全自动 | GitHub API 读取所有仓库 |
| 项目-比赛 AI 匹配 | ✅ 全自动 | 大模型打分，输出 Top 3 匹配 |
| 生成提交材料 | ✅ 全自动 | README、项目描述、演示脚本、标签 |
| 填写报名表 | ⚠️ 半自动 | 需要用户提供个人信息模板，自动填入 |
| 上传项目链接 | ✅ 全自动 | GitHub 链接直接填 |
| 结果跟踪 | ✅ 全自动 | 每5天自动访问记录页，状态变化推送 |
| 邮箱验证/协议签署 | ❌ 人工确认 | 涉及法律责任，必须本人操作 |
| 最终提交 | ❌ 人工确认 | 提交前给用户预览，确认后才提交 |

**原则**：Agent 做 90% 的准备工作，最后 10% 的提交动作由用户确认。绝不擅自提交。

---

## 三、什么样的比赛适合自动参赛

**必须同时满足**：
1. ✅ 线上比赛（不需要到现场）
2. ✅ 提交制（提交已有项目/作品，不是现场开发）
3. ✅ 允许个人参赛（不需要组队）
4. ✅ 报名免费（不需要付费）
5. ✅ 提交材料简单（项目链接 + 描述 + 可选视频）

**典型平台**：
- Devpost（大部分线上黑客松）
- Lablab.ai（AI 应用黑客松，提交制为主）
- 阿里云/腾讯云开发者大赛（线上提交）
- 各类 AI 应用挑战赛（提交 Demo 链接）

**不适合**：
- 48 小时现场开发黑客松
- 需要组队且人数 >1 的比赛
- 需要线下答辩/路演的比赛
- 有严格原创性要求（必须比赛期间从零开发）

## 四、核心流程

```
┌─────────────────────────────────────────────────────────┐
│  Step 1: 筛选可自动参赛的比赛                              │

└──────────────────────┬──────────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────────┐
│  Step 2: 扫描用户 GitHub 仓库                              │
│  读取所有仓库：名称、描述、技术栈、README、star、最近更新     │

└──────────────────────┬──────────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────────┐
│  Step 3: AI 匹配（项目 × 比赛）                             │
│  对每个「比赛-项目」对打分：                                │
│  - 主题匹配度（项目是否符合赛题方向）                        │
│  - 技术栈匹配（比赛要求的技术 vs 项目用的技术）              │
│  - 完成度（项目是否足够完整可展示）                          │
│  - 差异化（这个项目在该比赛中是否有竞争力）                  │
│  输出：每个比赛的 Top 3 推荐项目 + 匹配理由                  │
└──────────────────────┬──────────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────────┐
│  Step 4: 自动包装（为每个匹配生成比赛专用材料）              │
│  - 比赛专用 README（突出符合赛题的功能，重写项目介绍）       │
│  - 项目描述（200字/500字两版，针对比赛评分维度）            │
│  - 演示视频脚本（30秒/3分钟，告诉用户录什么）              │
│  - 标签/分类（比赛要求的赛道选择建议）                      │
│  - 提交说明（创新点、技术难点、社会价值）                    │
└──────────────────────┬──────────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────────┐
│  Step 5: 生成提交预览包                                    │
│  一个文件夹包含：                                          │
│  - README.md（比赛专用版）                                 │
│  - submission.md（提交表单需要填的所有内容，直接复制粘贴）   │
│  - demo_script.md（演示视频脚本）                          │
│  - match_report.md（为什么选这个项目参加这个比赛）          │
└──────────────────────┬──────────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────────┐
│  Step 6: 用户确认 → 半自动提交                             │
│  - 推送预览包给用户（飞书/邮件）                           │
│  - 用户确认后，自动打开比赛报名页，预填所有字段             │
│  - 需要人工的步骤（邮箱验证、协议签署）提醒用户完成         │
│  - 用户点最终提交 → 记录到 submitted_competitions.json    │
└──────────────────────┬──────────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────────┐
│  Step 7: 结果自动跟踪（提交后闭环）                        │
│  - 云电脑保存各平台登录态                                  │
│  - 每5天自动访问已提交比赛的记录页                         │
│  - 提取状态：报名成功→初审→入围→复赛→决赛→获奖/未获奖      │
│  - 状态变化立即推送（飞书/邮件）                            │
│  - 获奖时特别提醒 + 自动触发复盘模块                       │
│  - 登录态失效时提醒用户重新登录                            │
└─────────────────────────────────────────────────────────┘
```

## 五、AI 匹配评分模型

对每个「比赛 × 项目」组合，大模型按以下维度打分（0-100）：

```
总分 = 主题匹配 × 0.35 + 技术匹配 × 0.20 + 完成度 × 0.20 + 差异化 × 0.15 + 可包装性 × 0.10
```

| 维度 | 评分依据 |
|---|---|
| **主题匹配** | 项目核心功能是否符合比赛主题/赛道要求 |
| **技术匹配** | 比赛指定/鼓励的技术栈，项目是否使用 |
| **完成度** | 项目是否有可运行的 Demo、完整 README、截图/视频 |
| **差异化** | 相比该比赛常见参赛项目，这个项目是否有独特性 |
| **可包装性** | 能否通过改 README/描述就包装成符合比赛的样子 |

**输出格式**：
```json
{
  "competition": "比赛名称",
  "project": "仓库名",
  "total_score": 85,
  "dimension_scores": {
    "theme_match": 90,
    "tech_match": 80,
    "completeness": 85,
    "differentiation": 80,
    "packability": 90
  },
  "match_reason": "这个项目是AI客服机器人，比赛主题是企业级AI应用，技术栈完全匹配...",
  "packaging_advice": "建议突出多轮对话能力和企业知识库接入，弱化个人助手定位..."
}
```

## 七、使用方法

### 前置配置
1. 在 config.json 中填入 GitHub Personal Access Token（读取仓库用）
2. 填入个人信息模板（姓名、邮箱、简介，用于自动填表）
3. 配置推送通道（飞书/邮件，用于接收预览包和结果通知）
4. 在云电脑浏览器登录各比赛平台（保存登录态，用于结果跟踪）

### 运行
```bash
# 自动参赛（匹配+包装+预览）
python3 02-compass/auto_entry.py

# 结果跟踪（每5天自动运行，也可手动触发）
python3 02-compass/track_results.py
```

### 输出
- 每个可自动参赛的比赛，生成一个预览包文件夹
- 推送给用户确认
- 用户确认后，半自动完成提交
- 提交后自动进入结果跟踪队列

## 八、安全与合规

1. **绝不擅自提交**：所有提交动作必须用户确认
2. **原创性检查**：自动检查比赛规则是否允许"已有项目参赛"，不允许的跳过
3. **个人信息保护**：个人信息和登录态只存在本地，不提交到 git
4. **频率控制**：每天最多推荐 3 个比赛，避免用户疲劳
5. **质量优先**：匹配度低于 70 分的不推荐，宁可不参加也不要乱投
6. **登录态安全**：cookie 加密存储，只用于访问记录页，不做其他操作

## 十、结果自动跟踪（Step 7 详解）

> 提交完就不管了 = 白参加。自动跟踪比赛进度，获奖第一时间知道。

### 10.1 为什么需要自动跟踪

- 比赛周期长（提交后 1-3 个月才出结果），人工记不住
- 很多比赛结果不主动通知，需要自己去记录页查
- 获奖了但没看到 = 错过领奖/曝光/下一轮机会
- 未获奖也需要知道，好安排复盘和下一场

### 10.2 登录态管理（云电脑必备）

**首次配置**：
1. 在云电脑的浏览器里，逐个登录你参加的比赛平台
2. 登录态（cookie/session）自动保存到云电脑
3. 脚本读取 cookie 访问记录页，不需要每次登录

**登录态维护**：
- 每次跟踪前先检查登录态是否有效（访问一个需要登录的页面，看是否跳转到登录页）
- 失效时立即推送提醒：「XX 平台登录态已失效，请在云电脑重新登录」
- 用户重新登录后，跟踪自动恢复

**支持的平台**：
| 平台 | 跟踪方式 | 记录页特征 |
|---|---|---|
| Devpost | cookie + 网页抓取 | /dashboard 页面的 submissions 列表 |
| Lablab.ai | cookie + 网页抓取 | 个人中心的 my applications |
| 阿里云/腾讯云大赛 | cookie + 网页抓取 | 个人中心的参赛记录 |
| 通用平台 | cookie + CSS 选择器配置 | 用户自定义记录页 URL 和状态选择器 |
| 邮件通知 | 监听邮箱 | 很多比赛结果通过邮件通知，自动扫描关键词 |

### 10.3 定时跟踪策略

**频率**：每 5 天一次（太频繁浪费资源，太稀疏错过时间窗口）

**跟踪内容**：
1. 遍历 `submitted_competitions.json` 中所有已提交的比赛
2. 访问每个比赛的记录页
3. 提取当前状态（见下方状态机）
4. 和上次状态比对
5. 状态变化 → 立即推送
6. 状态不变 → 静默，只记录日志

**状态机**：
```
已提交 → 初审中 → 已入围/未通过
                ↓
            复赛中 → 晋级决赛/未晋级
                        ↓
                    决赛中 → 获奖(等级)/未获奖
```

每个状态变化都推送：
- 🟡 状态更新：「XX 比赛：初审中 → 已入围复赛！」
- 🔴 未通过：「XX 比赛：未通过初审，点击查看复盘建议」
- 🟢 获奖：「🎉 XX 比赛：获得二等奖！奖金 ¥5000，点击查看领奖指南」

### 10.4 获奖后的自动动作

检测到获奖时，自动触发：
1. **立即推送**：飞书/邮件/短信三通道通知（获奖是高优先级）
2. **生成领奖指南**：根据比赛规则，自动整理领奖步骤（确认信息、截止日期、需要提交的材料）
3. **触发复盘模块**：自动调用 `07-crystal/review_hackathon.py`，预填比赛信息，引导用户做获奖复盘
4. **更新项目档案**：把获奖信息写入项目的 GitHub README（可选，用户确认后执行）
5. **社交分享草稿**：生成小红书/朋友圈/推特的获奖分享文案（用户确认后发布）

### 10.5 未获奖后的自动动作

检测到未获奖时：
1. 推送通知，附安慰 + 鼓励
2. **自动触发复盘**：预填比赛信息，重点问「你觉得哪里没做好？」
3. **推荐下一场**：根据这个比赛的类型和你的项目，推荐 3 个类似的、胜率更高的比赛
4. **沉淀经验**：复盘完成后自动提 PR 到总仓库

### 10.6 数据存储

```json
{
  "devpost-ai-hack-2026": {
    "name": "Devpost AI Hack 2026",
    "platform": "devpost",
    "submitted_at": "2026-09-01",
    "project": "my-ai-project",
    "status": "已入围复赛",
    "status_history": [
      {"date": "2026-09-01", "status": "已提交"},
      {"date": "2026-09-10", "status": "初审中"},
      {"date": "2026-09-20", "status": "已入围复赛"}
    ],
    "result_url": "https://devpost.com/software/xxx",
    "last_checked": "2026-09-25"
  }
}
```

### 10.7 与定时任务的集成

在云电脑的 crontab 中增加：
```bash
# 每5天凌晨3点跟踪比赛结果
0 3 */5 * * cd /path/to/hackathon-bounty-hunter && python3 02-compass/track_results.py
```

跟踪脚本执行流程：
1. 读取已提交比赛列表
2. 逐个检查登录态
3. 抓取记录页状态
4. 比对状态变化
5. 有变化 → 推送 + 触发后续动作
6. 无变化 → 更新 last_checked，结束
