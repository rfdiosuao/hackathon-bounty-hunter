# 🏆 阶段 7：复盘结晶（Crystal）
> 比赛结束不是终点，而是下一次拿奖的起点。每一次复盘都让整个项目变得更强。
## 这个模块做什么
比赛结束后，引导使用者完成**结构化复盘**，自动分析失败原因，生成针对性优化建议，并**自动提交 PR 到总仓库**，形成「越多人用 → 越多人复盘 → 项目越强」的自进化闭环。
## 核心流程
```
比赛结束 → 运行复盘脚本 → 回答结构化问卷 → 自动分析短板
     ↓
生成复盘文档 → 自动创建分支 → 提交PR到总仓库 → 社区评审合并
     ↓
优化建议回流到对应模块（idea/UI/路演/...）
```
## 复盘问什么（必须问清楚）
### 1. 基本信息
- 比赛名称、参赛队名/个人名、比赛日期
- 最终成绩（获奖等级 / 未获奖 / 名次）
### 2. 七维度自评（1-5分）
| 维度 | 说明 |
|---|---|
| idea 创新性 | 点子够不够新，有没有差异化 |
| idea 实用性 | 是不是真需求，有没有人会用 |
| UI 设计 | 界面够不够炸，视觉统一度 |
| 交互体验 | 操作流畅度、反馈、细节 |
| 技术完成度 | 功能完不完整，稳不稳定 |
| 路演讲故事 | 讲得动不动人，逻辑清不清 |
| 时间管理 | 进度控制，有没有赶工 |
### 3. 失败原因（多选）
- idea 不够创新 / 不实用
- UI 不够好
- 功能不完整 / bug 多
- 路演没讲好
- 时间不够 / 进度失控
- 技术难点没攻克
- 团队协作问题
- 其他（自由填写）
### 4. 评委反馈（如有）
- 评委说了什么、打分情况、现场反应
### 5. 做对了什么（可复用经验）
- 这次哪些做法有效，下次可以沿用
### 6. 下次改进 Top 3
- 最想改进的 3 件事
## 自动分析逻辑
脚本根据自评分数和失败原因，自动定位核心问题并生成针对性建议：
| 短板维度 | 指向的优化模块 | 建议方向 |
|---|---|---|
| idea 创新性低 | 03-pathfinder + 反惯性提示词 | 用多视角审视重新生成 idea |
| idea 实用性低 | 02-compass 需求验证 | 先做用户访谈再动手 |
| UI 设计低 | 04-arsenal + 05-stage 秒哒蒸馏 | 参考获奖作品风格，先做设计稿再开发 |
| 交互体验低 | 05-stage UX_INTERACTION 模块 | 增加鼠标反馈、动效、错误处理 |
| 技术完成度低 | 05-stage PRODUCTION_FLOW 模块 | 倒推制作顺序，先做核心 demo |
| 路演讲故事低 | 06-sprint 路演模块 | 用痛点→方案→演示→愿景框架 |
| 时间管理低 | 倒推时间线模板 | 提前 2 周锁定功能，只做减法 |
## 自动提 PR
复盘完成后，脚本自动：
1. 创建分支：`review/{比赛名}-{队名}-{日期}`
2. 生成复盘文档到 `reviews/` 目录
3. 提交并创建 PR，标题：`复盘：{比赛名} - {队名}`
4. PR 内容包含：复盘摘要、短板分析、优化建议、可复用经验
社区成员可以评审 PR，合并后复盘经验沉淀到总仓库，供所有人参考。
## 使用方法
```bash
# 1. 配置 GitHub Token（首次）
cp config.example.json config.json
# 编辑 config.json，填入 github_token
# 2. 运行复盘
python3 07-crystal/review_hackathon.py
# 3. 按提示回答问题，完成后自动提 PR
```
## 配置项
| 字段 | 说明 |
|---|---|
| github_token | GitHub Personal Access Token（需要 repo 权限） |
| github_owner | 仓库所有者（默认 rfdiosuao） |
| github_repo | 仓库名（默认 prize-ops） |
| llm_api_key | 可选，大模型 API Key（用于生成更智能的优化建议） |
| llm_base_url | 可选，大模型 API 地址 |
## 复盘文档示例
生成的复盘文档会包含：
- 比赛基本信息
- 七维度评分（文字版雷达图）
- 失败原因分析
- 针对性优化建议（关联项目模块）
- 可复用经验
- 下次改进计划
