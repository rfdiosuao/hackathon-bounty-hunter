> 一套从发现比赛到拿奖的全流程工作流。任何人按这套流程执行，都能系统性地提高黑客松获奖概率。

## ⚡ 快速开始
```bash
# 1. 克隆
git clone https://github.com/rfdiosuao/hackathon-bounty-hunter.git
cd hackathon-bounty-hunter
# 2. 安装依赖
pip install requests beautifulsoup4
# 3. 配置（填入你的城市和飞书open_id）
cp config/config.example.json 01-radar/config.json
vim 01-radar/config.json
# 4. 运行扫描
cd 01-radar
python3 fetch_hackathons.py
python3 send_feishu.py
```
详细配置见 [docs/INSTALL.md](docs/INSTALL.md) 和 [docs/CONFIGURATION.md](docs/CONFIGURATION.md)。

## 核心理念
**不靠灵感，靠流程。** 黑客松获奖不是运气，而是可以被工程化的：
- 用情报系统发现高胜率比赛
- 用第一性原理拆解评审机制
- 用倒推法设计作品和路演
- 用标准化执行确保交付质量
- 用复盘闭环让每次比赛都更强

## 阶段一：情报雷达（Radar）
**目标：不漏掉任何一个高胜率比赛，在报名截止前发现它。**
### 信息源矩阵
| 来源类型 | 具体来源 | 覆盖范围 | 抓取方式 |
|---|---|---|---|
| **全球聚合** | HackHQ、Devpost、Lablab.ai、Eventbrite | 国际黑客松 | API/结构化抓取 |
| **中文聚合** | CSDN「AI赛事通」、SegmentFault活动、开源中国、掘金 | 国内技术赛事 | 网页抓取+搜索 |
| **小红书博主** | 杭州AI工坊、黑客松周报、数字小蕾 | 地域性/新兴赛事 | 笔记抓取+正文解析 ✅ |
| **活动平台** | 观猹 watcha.cn | 中文AI活动/黑客松聚合 | API结构化抓取 ✅ |
| **大厂官方** | 字节跳动、阿里、腾讯、百度、华为、Google、微软开发者平台 | 厂商黑客松 | 官网监控+RSS |
| **社区内容** | 微信公众号、知乎、B站、抖音 | 地域性/新兴赛事 | 搜索+OCR |
| **高校/政府** | 各地科委、高校创新创业学院、团委 | 官方赛事 | 定向监控 |
| **社群情报** | Discord、Slack、飞书群、微信群 | 内幕消息/延期 | 人工+机器人 |
### 情报处理流程
1. **多源抓取** → 原始数据（名称、时间、奖金、地点、链接、规则）
2. **结构化清洗** → 统一字段格式
3. **去重合并** → 同一比赛多来源合并，补全信息
4. **自动标签** → 按主题（AI/Web3/硬件/设计）、形式（线上/线下/混合）、难度分级
5. **截止倒计时** → 按截止时间排序，即将截止的标红预警
### 交付物
- 每日推送：新增比赛 + 即将截止提醒
- 比赛数据库：可搜索、可筛选的全量赛事库
- 个性化订阅：按主题/地域/奖金阈值过滤

## 阶段二：筛选罗盘（Compass）
**目标：从几十个比赛中，选出最适合你、胜率最高的那一个。**
### 评估维度
#### 1. 硬门槛过滤（一票否决）
- [ ] 身份要求（学生/在职/地域/年龄）
- [ ] 时间冲突（比赛时间 vs 你的日程）
- [ ] 技能匹配（技术栈要求 vs 你的能力）
- [ ] 团队要求（个人/组队/人数上限）
- [ ] 报名费用（免费/付费/差旅成本）
#### 2. 获奖概率评估
- **竞争度**：预计参赛队伍数 / 奖项数 = 获奖难度
- **评委偏好**：评委背景（技术/商业/设计）决定评分倾向
- **历史数据**：同主办方往届比赛的获奖作品特征
- **赛道分化**：多赛道比赛中，冷门赛道胜率更高
#### 3. 投入产出比
- **时间成本**：准备周期 + 比赛时长
- **奖金价值**：现金 / 算力 / 云资源 / 实习机会 / 曝光度
- **品牌价值**：主办方影响力、获奖后的职业加成
- **可复用性**：作品能否复用到其他比赛/项目
### 评分模型
```
综合得分 = 获奖概率 × 0.4 + 投入产出比 × 0.3 + 匹配度 × 0.3
```
输出：Top 3 推荐比赛 + 每个的推荐理由 + 风险提示

## 阶段三：深度分析（Pathfinder）
**目标：用第一性原理拆解比赛，找到最优获奖路径。**
> 本阶段基于 `competition-award-pathfinder` 方法论。
### 执行步骤
#### 1. 建立证据账本
- 收集所有官方规则、赛道说明、评审标准
- 每条事实标注：来源URL、查询日期、证据等级（official/runtime_clue/third_party/inference）
- 区分"规则要求什么"和"参赛者实际需要做什么"
#### 2. 硬门槛与规则冲突检查
- 提取：比赛周期、资格、提交数量、报名入口、平台要求、公网访问、文档要求、IP归属、宣传要求、评审阶段、评分维度、奖项、叠加规则
- 通用规则与赛道规则冲突时，取更严格的交集
- 输出冲突清单 + 需要向主办方确认的问题
#### 3. 重建评审漏斗
每个评审阶段都要分析：
- **进入条件**：什么情况下能进入下一阶段
- **评分维度**：评委看什么，权重多少
- **高概率失败模式**：大多数队伍死在哪里
- **评委可快速感知的信号**：30秒内能看到什么亮点
- **需要提供的验证材料**：Demo/文档/视频/数据
#### 4. 路线比较（至少3条）
一条完整路线 = 报名入口 + 提交方式 + 创作平台 + 作品原型 + 可叠加奖项 + 传播渠道
至少覆盖3种不同类型：
- 平台专项赛道路线
- 主赛道技术路线
- 设计/创意导向路线
- 成熟产品自报名路线
用 `evaluate_routes.py` 做确定性评估：硬门槛分类、Pareto 支配比较、奖项叠加计算。
#### 5. 解决关键未知项
如果某个未知信息会改变最优路线，设计最小验证动作：
- 假设 → 验证来源/操作 → 成功标准 → 时间盒
- 验证前只能给条件性推荐，不能标为确定最优
### 交付物
- 规则与证据表
- 硬门槛与失格风险清单
- 评审漏斗图
- 候选路线矩阵
- 推荐路线 + 被淘汰路线原因
- 待确认问题清单

## 阶段四：作品武器库（Arsenal）
**目标：从评分机制倒推作品设计，确保每个功能点都在为拿奖服务。**
### 反向设计流程
#### 1. 从评分维度推导核心功能
| 评分维度 | 作品必须体现的证据 |
|---|---|
| 创新性 | 独特的问题切入 / 技术组合 / 交互模式 |
| 完成度 | 完整可运行的核心链路，无报错 |
| 实用性 | 真实用户场景，可量化的价值 |
| 技术难度 | 至少一个有门槛的技术点 |
| 商业价值 | 可落地的商业模式 / 用户增长路径 |
| 社会价值 | 关注真实社会问题 |
#### 2. 作品五要素
1. **单一核心用户 + 高频痛点**：不要试图解决所有人的问题
2. **三步可理解的价值链**：用户进来 → 做什么 → 得到什么
3. **短Demo可见的功能证据**：30秒内展示核心价值
4. **匹配评委构成的记忆点**：
   - 技术评委 → 架构图/性能数据/技术难点
   - 商业评委 → 用户量/营收模型/市场规模
   - 设计评委 → 视觉规范/交互细节/品牌一致性
   - 人文评委 → 用户故事/社会影响/情感共鸣
5. **专业评审+传播渠道双用资产**：README、Demo视频、产品官网，既能给评委看也能传播
#### 3. 可复用组件库
- 登录/支付/图表等通用模块
- 路演PPT模板
- Demo视频脚本模板
- 项目文档模板
- 常见技术栈脚手架
### 交付物
- 作品概念说明（1页）
- 核心功能清单（带评分维度映射）
- Demo脚本（30秒/3分钟两版）
- 技术架构图
- 记忆点设计清单

## 阶段五：路演舞台（Stage）
**目标：用最有说服力的方式，在最短时间内征服评委。**
> 💡 **黑客松获奖公式：Idea 60% + UI 20% + 路演 20%**
> 内置 **UI 美学模块**（`05-stage/UI_AESTHETICS.md`）：蒸馏自外滩黑客松×秒哒应用美学黑客松的 13 个获奖作品，
> 包含 5 大可复用设计配方、7 大获奖 UI 设计逻辑、提交前自检清单。
> 内置 **交互逻辑模块**（`05-stage/UX_INTERACTION.md`）：蒸馏大赛官网的信息架构与交互逻辑
> （导航/CTA/信任状/时间线/卡片化），可反向应用于参赛作品与路演页。
> 内置 **交互动作层模块**（`05-stage/UX_INTERACTION_MOTION.md`）：蒸馏获奖作品的鼠标交互动作与反馈
> （按钮状态/输入反馈/实时预览/叙事加载/滑动叙事），附可复用交互动作库与检查清单。
> 内置 **流体动效模块**（`05-stage/HERO_FLUID_MOTION.md`）：源码级蒸馏官网首页交互式流体扭曲动效
> （Canvas 星点矩阵 + 鼠标跟随金色光斑 + 标题入场动画），附可复用配方与换色方案。
> 内置 **制作流程模块**（`05-stage/PRODUCTION_FLOW.md`）：倒推获奖作品的制作流程（先做图片资产还是先搭框架），
> 含 4 作品资产构成实证（纯代码/混合/重资产三路线）+ 7 步制作流程 + 零成本生图方案。
> 获奖作品档案（含 demo 链接与截图）：`05-stage/archive-miaoda/`
### 路演文档结构
1. **钩子（10秒）**：一个震撼的数据/故事/问题
2. **痛点（30秒）**：谁在什么场景下遇到什么问题，现在的解决方案为什么不好
3. **方案（60秒）**：我们做了什么，怎么解决的，核心创新点
4. **演示（90秒）**：现场Demo，展示核心链路
5. **壁垒（30秒）**：为什么我们能做成，技术/数据/团队优势
6. **商业（30秒）**：怎么赚钱/怎么增长/市场规模
7. **团队（20秒）**：为什么是我们这支队伍
8. **愿景（10秒）**：未来要成为什么
### 评委Q&A预判
- 提前列出20个最可能被问的问题
- 每个问题准备30秒标准答案
- 技术细节、数据来源、商业模式、竞争格局都要覆盖
### 提交检查清单
- [ ] 作品可公网访问
- [ ] Demo视频已上传
- [ ] README完整（安装/使用/架构/团队）
- [ ] 所有链接可访问
- [ ] 提交格式符合要求
- [ ] 截止时间前30分钟提交（留缓冲）

## 阶段六：执行冲刺（Sprint）

> 📖 核心心法：[最小可演示闭环](docs/minimum-demo-loop.md) — 用 20% 功能做出 80% 演示效果
### 倒排时间表
以提交截止时间为终点，倒推：
- **T-3天**：核心功能完成，开始打磨
- **T-2天**：Demo可跑通，开始写文档
- **T-1天**：路演稿完成，视频录制
- **T-12小时**：全流程测试，修复bug
- **T-6小时**：提交材料准备完毕

## 阶段七：复盘结晶（Crystal）
**目标：每次比赛都让下一次更强。复盘自动提PR，社区共建知识库。**
> 🔧 已实现：`07-crystal/review_hackathon.py` — 交互式问卷 + 自动分析 + 生成文档 + 自动提PR
### 复盘问什么
1. **基本信息**：比赛名称、队名、成绩
2. **七维度自评**：idea创新/实用、UI、交互、技术完成度、路演、时间管理（1-5分）
3. **失败原因**：多选（idea不行/UI不行/故事没讲好/...）
4. **评委反馈**：评委原话
5. **做对了什么**：可复用经验
6. **下次改进Top3**：具体动作
### 自动分析逻辑
- 找出最低分的2个维度
- 关联失败原因
- 生成针对性优化建议（指向项目对应模块）
- 生成Markdown复盘文档
- 自动创建分支 + 提交 + 创建PR到总仓库
### 资产沉淀
- 获奖作品案例库（`reviews/` 目录）
- 评委偏好数据库
- 可复用项目模板
- 工作流迭代记录

## 🚀 一键部署（Agent 自动部署）
### ⚠️ 硬性门槛
**本项目必须部署在云电脑上，且必须 24 小时在线。** 不建议本地部署，原因：
- 雷达需要定时扫描（每天 9:00 / 20:00），本地电脑关机就断
- 推送通道（飞书/邮箱/短信）需要持续在线
- 复盘模块需要随时响应
### 推荐云电脑平台
| 平台 | 特点 | 适合人群 |
|---|---|---|
| **TRAEWORK 云电脑版** | 稳定、性能好、支持长连接 | 追求稳定性的用户 |

### 📋 一键部署提示词（复制给你的 Agent）
把下面整段提示词复制给你的 Agent（豆包/Claude/GPT 等），它会自动完成全部部署：
```
# 角色
你是「黑客松赏金猎人」项目的部署工程师。你的任务是在当前云电脑环境中，一键部署整个项目，让它 24 小时自动运行：定时扫描全网黑客松 → 发现新比赛推送给用户 → 比赛结束后引导复盘并自动提 PR。
# 硬性前提检查（必须先确认，不满足就停止并告知用户）
1. 当前环境必须是云电脑，且能 24 小时在线（不是用户本地电脑）。
2. 必须有 Python 3.9+、pip3、git、curl。
3. 必须能访问外网（GitHub、各比赛信息源）。
4. 如果以上任一不满足，立即停止，告诉用户需要先准备云电脑（推荐 TRAEWORK 云电脑版 / 豆包工作云电脑版 / grokbot）。
# 部署步骤（按顺序执行，每步完成后汇报）
## Step 1：克隆项目
cd ~
git clone https://github.com/rfdiosuao/hackathon-bounty-hunter.git
cd hackathon-bounty-hunter
如果已存在则 git pull 更新。
## Step 2：安装依赖
pip3 install requests
检查 Python 版本：python3 --version（必须 3.9+）
## Step 3：配置用户信息
向用户询问以下信息（一次问完，不要分开问）：
1. 你所在的城市（用于筛选周边比赛，如：上海）
2. 推送通道：飞书 / 邮箱 / 短信（可多选，至少选一个）
3. 如果选飞书：需要用户的飞书 open_id（或让用户提供飞书机器人 webhook）
4. 如果选邮箱：SMTP 服务器、邮箱地址、授权码（QQ 邮箱用授权码不是密码）
5. 如果选短信：短信服务商 API（阿里云/腾讯云）的 AccessKey 和签名
6. 每天扫描时间（默认 9:00 和 20:00，可改）
将用户回答写入 01-radar/config.json（参考 config.example.json 的格式）。
⚠️ 敏感信息（token/授权码/API Key）只写入本地 config.json，绝对不要提交到 git。
## Step 4：配置信息源
项目默认集成以下信息源，确认每个都能访问：
- HackHQ（结构化 API）
- 观猹 watcha.cn（结构化 API）
- Lablab.ai（网页抓取）
- 大厂赛事页（微信/阿里/字节/百度黑客松）
- 小红书博主（3 个指定博主，需浏览器登录态）
- 微信公众号（需搜狗微信搜索或用户提供公众号列表）
如果某个源需要登录态（如小红书），告知用户需要在云电脑的浏览器里登录一次，登录态会保存。
## Step 5：测试抓取
运行一次抓取脚本，验证能拿到比赛数据：
cd 01-radar
python3 fetch_hackathons.py
检查输出的 latest_all.json 非空、有比赛名称和截止日期。
如果失败，排查网络/API 问题，修复后重试。
## Step 6：测试推送
用一条测试消息验证推送通道：
- 飞书：发送一条测试消息给用户
- 邮箱：发送一封测试邮件
- 短信：发送一条测试短信
确认用户收到后再继续。
## Step 7：配置定时任务
根据用户选择的扫描时间，设置定时任务：
- 如果是 Linux 云电脑：用 crontab 设置每天 9:00 和 20:00 运行 run_scan.sh
- 如果是豆包工作云电脑：用豆包的定时任务功能
- 如果是 TRAEWORK：用平台自带的定时任务
- 如果是 grokbot：用平台的 schedule 功能
定时任务执行的内容：
1. 运行 fetch_hackathons.py 抓取比赛
2. 运行中文搜索补充（关键词："2026 黑客松 报名"、"AI 竞赛 奖金"、"hackathon 中国"）
3. 合并去重，对比已推送记录
4. 有新增比赛则推送给用户（按用户配置的通道）
5. 更新已推送记录
## Step 8：配置复盘模块
确认 07-crystal/review_hackathon.py 可运行：
cd ../07-crystal
python3 -m py_compile review_hackathon.py
告知用户：比赛结束后运行 python3 07-crystal/review_hackathon.py 即可自动复盘并提 PR。
如果用户希望复盘也自动触发，可以配置：比赛截止日期后 3 天自动提醒用户做复盘。
## Step 9：部署验证
完成以上步骤后，输出部署报告：
- 项目路径
- 配置的信息源列表
- 配置的推送通道及测试结果
- 定时任务设置（执行时间、执行内容）
- 下次扫描时间
- 已知限制（如哪些信息源需要登录态）
## Step 10：日常维护说明
告诉用户：
- 项目会自动运行，不需要每天手动操作
- 如果推送收不到，先检查 config.json 配置和云电脑是否在线
- 想加新的信息源，编辑 01-radar/config.json 的 sources 字段
- 比赛结束后记得运行复盘脚本
- 项目更新：cd hackathon-bounty-hunter && git pull
# 注意事项
1. 所有敏感信息只存在本地 config.json，绝不提交到 git（确认 .gitignore 包含 config.json）
2. 抓取频率不要太高，避免被目标网站封 IP（每天 2 次足够）
3. 如果某个信息源挂了，跳过它继续其他源，不要因为一个源失败终止整个扫描
4. 推送内容要简洁：比赛名称、截止日期、报名链接、奖金、地点，5 个字段足够
5. 去重逻辑：按比赛名称前 30 字符 + 截止日期去重，避免重复推送
6. 部署完成后，给用户发一条确认消息（通过配置的推送通道），内容是"黑客松赏金猎人已部署成功，下次扫描时间：XX"
# 输出格式
部署完成后，用以下格式汇报：
✅ 部署成功
- 项目路径：xxx
- 信息源：x 个已配置
- 推送通道：xxx（测试已通过）
- 定时扫描：每天 xx:xx 和 xx:xx
- 下次扫描：xx
- 复盘模块：已就绪
- 已知限制：xxx
```
